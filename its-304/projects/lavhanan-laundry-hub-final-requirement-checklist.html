Lavhanan Laundry Hub — Final Requirement Checklist

Checklist for the Word document required by the SAD Final Requirement format. The template is saved in the vault as SAD - Final Requirement - Format.docx (School/atatchments/assets).

  • Working draft: Lavhanan Laundry Hub - Final Requirement Document
  • Decisions & running status: Lavhanan Laundry Hub - Final Requirement Progress & Context
  • Source material: Lavhanan Laundry Hub - System Context, Lavhanan Laundry Hub - Build Plan, finals
How to use this

Tick an item only when it is actually written or inserted in the Word file. Unchecked items are the remaining writing/design work. The template does not prescribe page counts — aim for complete but concise sections, and let the diagrams carry the technical detail.

0. Template setup

  • Copy the official template; keep its page size, margins, fonts, and heading styles
  • Replace NAME OF THE SYSTEM with Lavhanan Laundry Hub
  • Fill the title page: adviser, department, course, group members, month/year
  • Keep the TOC/List of Figures as Word fields so page numbers auto-update
  • Update the TOC and List of Figures last, after all pages settle
  • Add page numbers (lowercase roman for preliminary pages, Arabic for chapters)
  • Decide whether a References/Bibliography page is needed — the template does not show one
  • Decide whether Chapter V (Conclusion/Recommendations) is required — the template stops at Chapter IV
Template quirks to settle before writing
  • The List of Figures names 10 figures, but Chapter IV asks for more diagrams (context, class, activity, deployment, component, data dictionary). Recommended: keep the 10 required figures and add the extra diagrams to the list with new numbers.
  • ERD (Chen Notation) and Data Entity Diagram both appear. Treat ERD as the conceptual model (entities/relationships) and Data Entity Diagram as the physical schema (tables/columns).
  • V-model is a methodology figure, but it is listed under List of Figures. Put the figure in Chapter III and list it as Figure 1.
  • List of Appendices is empty in the template. Add appendices only if the instructor allows them; otherwise remove the page or leave it blank.
  • The TOC says "Reviews of Related Literature and Studies"; the conventional heading is "Review of Related Literature and Studies". Keep the template wording if the instructor is strict.
  • The TOC page numbers in the template are placeholders (1). They must be regenerated, not typed by hand.

1. Preliminary pages

  • Title page — system name, submission statement, adviser, department, course, group members, month/year
    • Confirmed: Owen N. Estrera, Sam Rich John L. Orcullo, Samantha S. Academia, Ezra Jean A. Tejeros, Sham M. Leon
    • Still missing: month/year of submission
  • Table of Contents — all headings down to third level; page numbers correct
  • List of Figures — number, caption, page; every figure in the paper appears here
  • List of Appendices — letter, title, page (if appendices are used)

2. Chapter I — The Problem and Its Scope

  • Introduction — business background, location, hours, services, current manual workflow, why the system is needed
  • The Problem — the five concrete problems:
    • handwritten logbook and paper receipts → incomplete, hard-to-search records
    • unverified clothing counts → missing-item disputes
    • manual follow-up of unpaid/unclaimed orders → slow, easy to forget
    • manual daily sales totaling → slow and error-prone
    • no customer-facing status → customers call or visit to ask
  • Beneficiaries — Owner/Admin, Manager, Cashier, Labandera, customers, future delivery driver, the business
  • Scope and Limitations of the design — what the design covers, what it deliberately does not:
    • responsive web app for staff and customers
    • Android users via browser; no native Android app in the prototype; no iOS native app
    • SMS notifications through a gateway; the prototype uses a mock outbox
    • thermal receipt via 72 mm browser print, not direct ESC/POS
    • server at the shop; local Wi-Fi; internet needed for SMS and remote access
    • no online payments, barcode/RFID, digital scale, or multi-branch support
    • SUKI CARD loyalty is future work

3. Chapter II — Review of Related Literature and Studies

  • Opening paragraph: what the review covers and how sources were selected
  • Related Literature — at least these themes:
    • laundry / service-business management systems
    • SMS notifications and automated customer reminders
    • order-status tracking and customer self-service portals
    • role-based access control and data privacy
    • systems development models (V-model, SDLC, Agile)
  • Related Studies — 5–10 credible local/foreign studies; table with author/year, focus, method, findings, relevance
  • Synthesis — the gap: an affordable, offline-tolerant, SMS-enabled laundry system for a small shop
  • APA 7 in-text citations; full reference list (or bibliography) at the end
  • Verify every source is real and accessible; no placeholder citations in the final file
Source hunting

Use Google Scholar, ResearchGate, and Philippine university repositories. Search: laundry management system, SMS notification system customer, order tracking system small business, role-based access control web system, V-model software development. Record the DOI/URL and access date as you go.

4. Chapter III — Methodology

  • Design — explain the chosen model and why
    • V-model figure (Figure 1) and phase descriptions
    • left side: requirements → system design → architecture/component design → implementation
    • right side: unit → integration → system → acceptance testing
    • traceability: every requirement maps to a design element and a test
    • development tools: Symfony 8.1, PHP 8.4+ (worked on 8.5), MySQL 8, Doctrine, Twig, PHPUnit, Docker, Git, draw.io
  • Instrument use in data gathering
    • semi-structured interview guide (owner/manager/staff)
    • observation checklist (order intake, weighing, receipt, status updates, pickup/payment)
    • document review (logbook pages, receipts, price list, promo materials)
    • user acceptance / demo checklist
    • optional customer questionnaire
  • Data gathering procedures
    • permission letter and owner consent
    • interview schedule and participants
    • shop observation dates and workflow notes
    • sample documents collected
    • how responses became requirements
    • requirements validation/sign-off
  • Ethical considerations — voluntary participation, anonymity, secure storage, RA 10173 (Data Privacy Act)

5. Chapter IV — Project Description & Technical Background

  • Project description — purpose, target users, major features, development context
  • Technical background — architecture, stack, hosting model, integrations

Logical Design

  • Context Diagram — system boundary + external entities (Owner/Admin, Manager, Cashier, Labandera, Customer, SMS gateway)
  • Use Case Diagram — actors, use cases, includes/extends; short actor/use-case table
  • Class Diagram — User, Customer, LaundryOrder, OrderItem, Service, OrderStatusLog, SmsLog; relationships and multiplicities
  • Activity Diagram — order intake → washing → drying → folding → ready (SMS) → claimed; payment and delete-block decisions
  • Entity Relationship Diagram (Chen Notation) — entities, attributes, relationships, cardinality
  • Data Dictionary — one table per entity or one consolidated table: field, type, length, null, key, default, description

Physical Design

  • Architectural Diagram — browser → Symfony → Doctrine → MySQL; Messenger worker → Notifier → SMS gateway
  • Deployment Diagram — shop server/PC, Docker services, local Wi-Fi router, client devices, internet/SMS gateway
  • Component Diagram — controllers, services, repositories, entities, notifier transport, console commands, Twig templates
  • User Interface — screenshots with captions:
    • login
    • owner dashboard
    • order list + search/filter
    • order form (service, weight, items)
    • order detail + status buttons
    • thermal receipt
    • customer portal
    • sales reports
    • SMS outbox
    • help/tutorial page
  • Hardware requirements — minimum and recommended tables:
    • server/PC (CPU, RAM, storage, OS)
    • router/local network
    • staff devices (Android phone/tablet or PC)
    • thermal receipt printer (58/72 mm)
    • UPS/backup power
    • internet connection for SMS/remote access
    • backup storage

7. Appendices (optional, confirm with instructor)

  • Appendix A — Interview guide/questions
  • Appendix B — Observation checklist
  • Appendix C — Sample receipt / order slip
  • Appendix D — Additional UI screenshots
  • Appendix E — Source code excerpts (routes, controllers, entities)
  • Appendix F — Test results (81 tests / 435 assertions)
  • Appendix G — User manual / demo accounts

8. Final QA

  • Every figure and table is mentioned in the text
  • Figure/table numbering is sequential and matches the lists
  • TOC and List of Figures regenerated
  • Page numbers correct (roman vs Arabic)
  • Headings follow the template's numbering (I, II, III, IV; 1.1, 1.2, …)
  • Spelling, grammar, punctuation
  • Citations and references consistent (APA 7)
  • No placeholder text ([insert], TODO, Student 1)
  • Word file exported to PDF and both backed up
  • Plagiarism/similarity check if required
  • File name follows the instructor's required format

9. Submission pack

  • Word document (.docx)
  • PDF copy
  • Figures exported as PNG/PDF (keep editable sources: .drawio, .puml)
  • Source code / repository link (if requested)
  • Demo account list and run instructions (optional appendix)

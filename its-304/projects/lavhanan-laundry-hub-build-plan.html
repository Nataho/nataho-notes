Lavhanan Laundry Hub — Build Plan

Built in C:\Users\Nataho\Documents\school\sys ad\finals (Symfony 8.1, PHP 8.4+). Spec: Lavhanan Laundry Hub - System Context ← finals + rubric + opening-kit PDFs.
Patterns reference: previous project C:\Users\Nataho\Documents\school\webdev\symfony\finals.

Environment
  • Run tools via Windows: symfony (scoop), composer, php.exe (8.5, has pdo_mysql) — no PHP in the WSL distro
  • Docker Desktop runs on Windows; docker compose driven through the Windows binary
  • Brand: green #0C4A23, red #9C001D, white glyph logo (from Lavhanan Logo.pdf)

Milestone 1 — Core staff flow + rubric-critical features

1. MySQL on Docker (reuse previous project's setup)

  • compose.yaml: lav-mysql (mysql:8.0, port 6971→3306) + lav-phpmyadmin (6972), volume lav-db-data, network lav-network
  • .env: MYSQL_* vars (db laundry_hub, user lavuser) + DATABASE_URL template + real APP_SECRET
  • docker compose up -d via Docker Desktop, Doctrine connects

2. Data model + migrations

Entity style follows the previous project (named columns, collection helpers). Roles use the standard JSON column + role_hierarchy.

  • User — email, name, phone, password, roles JSON, isActive (disable/archive accounts)
  • Service — catalog (Full Wash ₱180 … Fold ₱15), weight limits, inclusions
  • Customer — name, phone, nullable login link
  • LaundryOrder — code, customer, service, weight, item counts, total price, status, payment status, instructions
  • OrderItem — clothing type + count (lost-item proof)
  • OrderStatusLog — step, by whom, when
  • Migration run; seed command (demo users per role, real service catalog, demo orders)

3. Auth & access control (rubric: 17+11 pts)

  • security.yaml: firewall, role_hierarchy, access_control paths
  • AppAuthenticator + login/logout pages + CSRF
  • Role-aware base layout (Twig role menus)
  • Profile page + change-own-password (all roles)
  • Unauthorized access → 403 / redirect; staff blocked from admin pages

4. Admin features (rubric: 19 pts)

  • Admin dashboard: total users, total staff, total orders, recent activity
  • User management CRUD: create (staff/admin), view all (name/email/role/date created), edit (name/email/role), reset password, delete with confirmation, disable/archive account

5. Cashier flow (CRUD, rubric: 15+16 pts)

  • New order: pick/create customer, service (auto price), weight validation (8kg/5kg), clothing items with counts, add-ons, payment status
  • Order list + search & filter; edit own orders (cashier), manager/admin edit any
  • Receipt view (thermal-printer friendly), delete with confirmation (unpaid delete blocked)

6. Labandera flow

  • Status buttons: Washing → Drying → Folding → Ready; every change logged to OrderStatusLog

7. Tests

  • WebTestCase: login per role, order create, status walk, 403 for staff on admin routes, delete-block for unpaid — 23 tests / 73 assertions, all green

Running it (demo)

bash
docker compose up -d              # lav-mysql :6971, lav-phpmyadmin :6972, Mailpit :8025 (UI) / :1025 (SMTP)
symfony console app:seed-demo     # idempotent: menu, accounts, 3 demo orders
symfony console messenger:consume async   # SMS worker — delivers queued texts to the outbox
symfony serve                     # http://127.0.0.1:8000 (or :8001)
symfony php bin/phpunit           # test DB: laundry_hub_test
Compose project renamed

The compose project is now lavhanan (name: key in compose.yaml) — both this and the old webdev project live in folders named finals, which made Docker Desktop group them together and let docker compose stop from either folder stop both stacks. Now each folder scopes to its own containers. DB data moved via a raw datadir copy (finals_lav-db-data → lavhanan_lav-db-data, old volume removed; safety dump in var/backups/db-pre-rename.sql). Mailpit ports pinned to the documented 1025 (SMTP) / 8025 (web UI) instead of random ephemeral ports.

M2 customer flow: open http://127.0.0.1:8001/register → sign up with a new phone (fresh empty portal) or with a walk-in's phone (0918 771 0092 = Lito) to inherit their LH-DEMO-0002 history — the account auto-logs in straight to "My laundry". Portal updates itself every 30 s.

M3 SMS flow: keep messenger:consume async running, then as the labandera advance LH-DEMO-0003 to Ready → the text lands at /admin/sms (Owner) within seconds. symfony console app:remind-unclaimed --dry-run previews who would get nudged; the ⚡ button broadcasts an outage notice to every customer with laundry on the machines.

M4 reports flow: log in as Owner → Reports (nav) → Today / This month / a custom range. The cards show paid vs unpaid and the average bill; the day-by-day table and per-service table break it down, and Download CSV saves the same numbers with a totals row. /help (nav "Help") gives every role its own quick start; the video slot says "coming soon" until the recording is added in a later update.

Gotchas hit during the build
  • Symfony 8 needs #[MapEntity(mapping: ['code' => 'code'])] on actions that route orders by {code} (non-identifier args no longer auto-resolve)
  • Form errors added in a PRE_SUBMIT listener get wiped by the child's own submit() — customer-required check lives in POST_SUBMIT
  • render() auto-returns 422 when the form is invalid; entities may carry no assert that the controller only satisfies after form validation (customer)
  • Symfony 8 CSRF: stateless ids (submit, authenticate, logout) validate by same-origin header or double-submit cookie — browsers are fine, raw curl needs -H "Origin: ..."

M2 gotchas:

  • Symfony 8 Voter::voteOnAttribute() must accept the new 4th param ?Vote $vote = null, or the container fails to compile
  • Windows curl from WSL: -o /dev/null aborts with exit 23 (and cookie jars from -c never get written); write to NUL, and pass the session manually as -H "Cookie: PHPSESSID=..." captured from -D -
  • AssetMapper serves controllers only at their hashed URLs (/assets/controllers/auto_refresh_controller-<hash>.js) — unhashed paths 404 even though debug:asset-map lists the asset; grab the real URL from the rendered page
  • Demo seed data had duplicate walk-in rows (same name+phone); M2 smoke merged them — customers are now ids 1–3, each owning one LH-DEMO-000x order
  • ⚠️ docker compose down -v deletes the data volume (lavhanan_lav-db-data) — for daily stop/start use docker compose stop or down (no -v). A stop error actually aborts down -v before volume removal, which is why a near-miss stayed harmless; restore point: var/backups/db-pre-rename.sql

M3 gotchas:

  • A when@test: block inside a bundle config file must nest under the extension name that file belongs to (messenger.yaml → when@test: framework: messenger:) — when@test: messenger: is read as a nonexistent "messenger" extension and the container won't compile
  • Blank phones ('') pass a plain null check and make SmsMessage throw (needs a phone number) — treat a phone as "no phone" after trim(); old test-DB rows do contain empty phones
  • The test DB keeps rows between runs, so outbox assertions must be scoped per order (SmsLogRepository::findForOrder()) — global row counts and the flash count are nondeterministic
  • make:migration picked up an unrelated order_total_amount DEFAULT '0' vs '0.00' drift — deleted from the migration; keep migrations to the feature's tables
  • DoctrineBundle 3 has no doctrine:query:sql anymore — use doctrine:query:dql (enum fields come back as \stdClass envelopes, values under ->value)

M4 gotchas:

  • Doctrine DQL has no DATE() function — group by day with SUBSTRING(o.createdAt, 1, 10) (MySQL casts the datetime to text); GROUP BY and ORDER BY accept the result alias (day)
  • Fixed-date report tests collide with the shared test DB on rerun — delete prior LH-RPT-% rows at test start; don't assert global totals against today's date
  • PHP 8.5 deprecates fputcsv()'s implicit $escape — pass ',', '"', '' explicitly
  • The M4 smoke's raw PowerShell login failed with "Invalid CSRF token" until it sent Origin/Referer: stateless authenticate CSRF validates same-origin, and the form value is literally csrf-token (the cookie name), not a session token
  • /help shows the admin guide only to admins and staff guides only to staff, so customers never see links into /admin or /orders that would 403

Milestone 2 — Customer portal ✅ done

  • /register: name, email, required phone, optional address, repeated password (RegisterType + RegistrationController)
  • History linking: phone matches a walk-in Customer → login attaches to that record (past orders appear at once); no match → new Customer; phone already has a login → form error ("log in instead")
  • Auto-login after signup (UserAuthenticatorInterface + AppAuthenticator) → straight to /my with success flash
  • security.yaml: ^/register PUBLIC_ACCESS before the ^/ catch-all; signed-in users bounce home; "Create account" link on the login page
  • CustomerOrderVoter (VIEW on an order): customer = own tickets only → 403 otherwise; staff delegate to OrderService::canView() — one source of truth used by the portal detail, OrderController::show and the receipt
  • /my/{code}: customer-safe ticket page (status timeline, clothing counts = lost-item proof, add-ons, amount due, payment badge) — zero staff buttons
  • Live status: auto_refresh Stimulus controller re-fetches the portal every 30 s, pauses while the tab is hidden, keeps open cards open
  • Tests: tests/Functional/CustomerPortalTest.php (9 tests) — registration + linking + auto-login, walk-in history attach, same-phone rejection, mismatched passwords, taken email, own-ticket-only isolation (403s), own detail content, staff still view via voter
  • Full suite green: 32 tests / 131 assertions; lint:container + lint:twig pass; live smoke: register → auto-login → portal, walk-in linking, same-phone → 422, other's ticket → 403, detail shows counts/timeline/total with no staff buttons

Milestone 3 — SMS notifications ✅ done

  • Mock outbox gateway: custom Notifier transport behind SMS_DSN=sms://outbox — every text is persisted to sms_logs (phone, from, body, trigger, ticket); going live later = composer require symfony/twilio-notifier + one DSN change
  • App\Notifier\OutboxTransportFactory — FrameworkBundle auto-tags every TransportFactoryInterface as texter.transport_factory, zero YAML service wiring; notifier.yaml maps texter_transports.sms to the env DSN
  • Ready-for-pickup text: OrderService::changeStatus() dispatches when a ticket enters Ready (async via Messenger — SmsMessage: async routing was pre-wired); a manager revert → re-advance sends a fresh text on purpose
  • app:remind-unclaimed [hours] [--dry-run]: texts tickets Ready for > 24 h; at most one reminder per order per day (checked against the outbox log)
  • Power-outage broadcast: Owner/Admin button on /admin/sms + confirm dialog, texts every customer with laundry on the machines (one per customer, blank phones skipped), CSRF-guarded
  • /admin/sms outbox page (Admin only, nav "SMS" link): sent time, recipient, trigger filter chips, message, ticket link; badge-trigger-* classes in app.css
  • Tests: tests/Functional/SmsNotificationTest.php (7 tests) — ready-text content + order link, earlier steps send nothing, re-Ready re-texts, reminder command + same-day dedup (--dry-run first), outage only to in-progress customers, outbox/broadcast 403 for staff, payment change sends nothing
  • Test env runs Messenger async as sync:// (when@test block in messenger.yaml) so outbox rows exist the moment the action returns — no worker needed in tests
  • Full suite green: 39 tests / 168 assertions; lint:container + lint:twig pass; live smoke: command → doctrine queue → worker → outbox row (Lito, LH-DEMO-0002)

Details and gotchas: Lavhanan Laundry Hub - Project Assistant

Project Assistant gotchas
  • The Messenger worker (symfony console messenger:consume async) must be running for chat replies and publishing.
  • php_fileinfo is missing in this PHP build — uploads are validated by extension, stored outside the web root, never executed.
  • Teammates must be excluded from isCustomer() and redirected in both HomeController and AppAuthenticator, or login lands on /orders (403) / /my.
  • Judges at #high reasoning were too slow (~3 min); #low keeps a full live reply around a minute.
  • Judges now receive the recent chat history (40 messages) + compacted summary; teammate-stated facts are valid evidence, so a name given in one turn can be applied by a later “apply that”.
  • Blocked patches lead with Nothing was changed; the model is instructed to phrase edits as proposals, not completed actions.
  • Judge verdicts are split: patch issues block the edit, reply issues only withhold the reply, so a wording error never discards a correct patch.
  • Publishing the notes site is allowed while [MISSING] markers remain; only contradictions and drift are blocked.
  • A long-running dev worker leaks memory from Doctrine's debug backtraces and dies at PHP's 128 MB limit after ~1.5 h. Run it in prod with headroom: php -d memory_limit=512M bin/console messenger:consume async --env=prod --memory-limit=384M.

Part I. Identification

Directions

Write the correct SDLC phase described in each statement.

  1. Establishes project goals, scope, feasibility, and risks.
    Answer: Planning Phase

  2. Gathers functional and non-functional requirements from stakeholders.
    Answer: Analysis Phase

  3. Creates system architecture, interface designs, and workflows.
    Answer: Design Phase

  4. Develops the actual software using programming languages.
    Answer: Coding Phase / development phase

  5. Ensures the software meets quality standards through testing.
    Answer: Testing

  6. Releases the completed software to users.
    Answer: Deployment phase

  7. Provides updates, bug fixes, and continuous improvements.
    Answer: Maintenance Phase

Part II. Scenario-Based

Scenario Context

Task

Complete the table below by identifying what activities should be performed during each SDLC phase for this project.

SDLC Phase Example Activity
Planning Defining project scope, budget and deadlines

Design Creating screen mockups and database layouts
Development Coding the web portal and approval database

Part III. Reflection

Directions

Answer the following questions in 3–5 sentences each.

1. Why is Requirement Analysis considered one of the most important phases of the SDLC?

Answer

Requirement analysis shows the exact goals, features and constraints of the software before any design or coding starts. Knowing stakeholder needs early will prevent expensive rework, project delays, and misunderstandings in the development cycle. It also gives the needed blueprint that guides the design, development and testing tasks

2. What problems might occur if the Testing phase is skipped before deployment?

Answer

The software might have bugs when it is deployed. Many customers or users will have many complaints on said bugs. Customers may stop using your software because it has proven that it's unreliable to them because of the bugs that were overlooked.

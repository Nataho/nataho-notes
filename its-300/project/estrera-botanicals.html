Estrera Botanicals — final project checklists

from Rubrics for Final Project (extracted text) ← Rubrics for Final Project.pdf (source of truth)
[x] = verified in the actual code · numbers in () = rubric points

basic checklist — core requirements

auth & roles

  • Working login & logout system (6) — /login + AppAuthenticator + remember-me
  • Proper password hashing & security (5) — auto hasher, applied on signup & password change
  • Unauthorized access properly blocked (2) — /shop access rule; /account behind denyAccessUnlessGranted
  • Correct role implementation: Admin & Staff (4) — admin exists, no staff tier yet → advanced

authorization

  • Proper access denial, 403 / redirect (3) — users hitting restricted pages get blocked or re-routed
  • Role checks in controllers & templates (3) — isGranted(...) + is_granted("ROLE_ADMIN") throughout

crud

  • Create (4) — admin adds products (with image); customers create orders & addresses
  • Read (3) — shop grid, account tabs, order logs with status filters
  • Update (4) — partial: stock update + address edit only, no full product edit → advanced
  • Delete with confirmation (4) — confirm modals + typed-phrase deletes, all CSRF'd

admin basics

  • View all data records (3) — users tab, stock tab, all-orders logs (searchable)
  • Admin dashboard, totals (3) — user / product / order counts + recent orders

validation & security

  • Form validation (4) — #[Assert\...] constraints + per-field checks
  • Flash messages (2) — success & error on every action
  • CSRF protection (3) — every action token'd and validated
  • No plain-text passwords (2)

ui & code quality

  • Clean layout & navigation (3)
  • Role-based menu display (2)
  • Mobile readability (3) — needs one phone check
  • Clean controller usage (1)
  • Proper entity & repository usage (1) — partial: some raw SQL in AccountController
  • Organized templates & routes (1)

advanced checklist — remaining points

  • ROLE_STAFF role tier (4) — small change in Entity/User.php; unlocks everything below
  • Admin user CRUD (13) — create user/staff (5) · update (4) · delete with confirm (4)
  • security.yaml role rules (5) — dedicated access_control rules for admin routes
  • Staff record CRUD, own records only (16) — create (6) · edit own (6) · view (4); needs an ownership column on products + staff blocked from admin pages
  • Full product edit form — completes Update (4)
  • Date-created column in the users tab
  • Real 403 page on manual URL bypass
  • One phone-pass on the layout — completes Mobile (3)

score estimate ≈ 59.5 / 100 (basic 55.5 of 67 earned · advanced 0 of 33) — partials noted inline; grader may weigh them differently.

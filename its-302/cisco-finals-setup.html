Cisco Finals Setup

#verifyLast updated: Nov 12, 2026
Scenario

one big network in two "pods", everything joined at the 3560 (Multilayer Switch0) — the rubric is basically "make the network work as taught":

VLAN 10 192.168.10.1 — the dhcp vlan (pool lives on the 3560)
VLAN 20 192.168.20.1
VLAN 30 192.168.30.1
VLAN 100 192.168.100.1
VLAN 200 192.168.200.1

ip pattern: end devices get .10 / .11, anything router-ish gets .101 / .102 — and devices behind the wireless routers stay in the wrt300n's own lan

How to start

prepare the main switch (3560-24PS)

prepare the 5 sub switches (2950T-24)

prepare the router (1941) and 2 wireless routers (WRT300N)

prepare the end devices (server, pcs, smartphone)

the cabling rule used all through this build

gigabit ports are reserved for switch↔switch and switch↔router links first, fast ethernet is for end devices (pcs, servers, the wrt300n lan side, phones)

connect the pcs and server to their switches

connect them all using straight through cables on fast ethernet ports

configuration

switch0 Fa0/1 to server0 Fa0
switch0 Fa0/2 to pc0 Fa0
switch0 Fa0/3 to wireless router0

switch1 Fa0/1 to pc4 Fa0
switch1 Fa0/2 to pc5 Fa0
switch1 Fa0/3 to wireless router1

switch2 Fa0/1 to pc2 Fa0
switch2 Fa0/2 to pc3 Fa0

switch4 Fa0/1 to pc7 Fa0
switch4 Fa0/2 to pc8 Fa0
switch4 Fa0/3 to pc9 Fa0

connect the switches to each other

every switch↔switch link is a cross over cable on gigabit ports — these all become trunks later

configuration

multilayer switch0 Gig0/1 to switch1 Gig0/1
multilayer switch0 Gig0/2 to switch0 Gig0/1
switch0 Gig0/2 to switch3 Gig0/1
switch3 Gig0/2 to switch4 Gig0/1

connect the 1941 router

straight through cables — the router side is always one of its two gigabit ports, the switch side is the free gig port

configuration

router0 Gig0/0 or Gig0/1 to switch1 (hover the cable ends to check which is which — it doesn't matter, no ips go on the router)
router0 other gig port to switch2 Gig0/1

add the wireless routers

wireless router0 → switch0 and wireless router1 → switch1, straight through into the wrt300n's internet port. then pc1/pc6 into its lan ports and smartphone0 connects over wifi

Full tree

the setup

before anything, remember the exit ritual you'll do over and over: no shutdown → exit → do wr — exit guide

who owns what

the 3560 owns every gateway (192.168.x.1) — same rule as the dhcp lab, no other device gets an svi with an ip. the 1941 router only gets its ports turned on: routing it wasn't taught, so the vlan100 pod behind it stays local (explained at the router section)

enter the main switch (3560)

click the switch → cli tab, then — enable guide, configure terminal guide

cisco
Switch>                 enable
Switch#                 configure terminal
Switch(config)#

main switch (3560)

create the 5 vlans

one block, all five — create vlan guide

if your rubric asks for vlan names

type name [vlan name] right after entering each vlan N — rename vlan guide

cisco
Switch(config)#         vlan 10
Switch(config-vlan)#    exit
Switch(config)#         vlan 20
Switch(config-vlan)#    exit
Switch(config)#         vlan 30
Switch(config-vlan)#    exit
Switch(config)#         vlan 100
Switch(config-vlan)#    exit
Switch(config)#         vlan 200
Switch(config-vlan)#    exit
Switch(config)#         do wr

svi for vlan 10

the gateway for the whole dhcp vlan — vlan interface + ip address guide, exit guide

cisco
Switch(config)#         interface vlan 10
Switch(config-if)#      ip address 192.168.10.1 255.255.255.0
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr

svis for the other 4 vlans

same block, swap the vlan number and ip each time:

cisco
Switch(config)#         interface vlan 20
Switch(config-if)#      ip address 192.168.20.1 255.255.255.0
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr
cisco
Switch(config)#         interface vlan 30
Switch(config-if)#      ip address 192.168.30.1 255.255.255.0
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr
cisco
Switch(config)#         interface vlan 100
Switch(config-if)#      ip address 192.168.100.1 255.255.255.0
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr
the vlan100 svi is "for completeness"

pc2/pc3 sit behind the 1941 router, which doesn't route — so nothing in that pod can actually reach this gateway. it's set anyway so the switch matches the "all 5 vlans" pattern

cisco
Switch(config)#         interface vlan 200
Switch(config-if)#      ip address 192.168.200.1 255.255.255.0
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr
after the last svi you'll see the link up messages like this

%LINK-5-CHANGED: Interface Vlan200, changed state to up

trunk on the main switch (3560)

both gig uplinks get trunked in one range block — Gig0/1 points at switch1 and Gig0/2 points at switch0 — enter interface guide, trunk guide, exit guide

the encapsulation dot1q line is only needed/possible on the 3560
cisco
Switch(config)#         interface range gigabitEthernet 0/1 - 2
Switch(config-if-range)# switchport trunk encapsulation dot1q
Switch(config-if-range)# switchport mode trunk
Switch(config-if-range)# no shutdown
Switch(config-if-range)# exit
Switch(config)#         do wr

after this the main switch side is done — it should show Vlan10, Vlan20, Vlan30, Vlan100 and Vlan200 up in show ip interface brief

sub switches (2950T)

this part repeats on all five — switch0, switch1, switch3, switch4 and switch2. do the whole section on one device, then click to the next

enter each sub switch

it's a different device, so you have to enable + configure terminal on it again:

cisco
Switch>                 enable
Switch#                 configure terminal
Switch(config)#
check the ports first

hover the cable ends or run show ip interface brief to see what's actually plugged where — the ports below follow the "gigabit for switches/router, fast ethernet for end devices" rule

trunk on every sub switch

the 2950 only supports 802.1Q so there is no switchport trunk encapsulation command here — just mode trunk. and since both gig ports end up as trunks anyway, the range trick knocks them out in one block (a gig with nothing plugged in just stays idle). second switch trunk guide, exit guide

cisco
Switch(config)#         interface range gigabitEthernet 0/1 - 2
Switch(config-if-range)# switchport mode trunk
Switch(config-if-range)# no shutdown
Switch(config-if-range)# exit
Switch(config)#         do wr

same block on all five sub switches — what the gigs point at:

switchgig portspointing at
switch0Gi0/1, Gi0/2multilayer switch0, switch3
switch1Gi0/1, Gi0/2multilayer switch0, router0
switch2Gi0/1 (Gi0/2 empty)router0
switch3Gi0/1, Gi0/2switch0, switch4
switch4Gi0/1 (Gi0/2 empty)switch3

create the 5 vlans on every sub switch

the 2950 needs its own copy of the vlans (vtp may sync them over the trunk, but making them by hand is safer) — second switch vlan guide

cisco
Switch(config)#         vlan 10
Switch(config-vlan)#    exit
Switch(config)#         vlan 20
Switch(config-vlan)#    exit
Switch(config)#         vlan 30
Switch(config-vlan)#    exit
Switch(config)#         vlan 100
Switch(config-vlan)#    exit
Switch(config)#         vlan 200
Switch(config-vlan)#    exit
Switch(config)#         do wr

access ports — the range trick

first make all the end-device ports access ports in one go with a range, then drop each port into its vlan one by one:

cisco
Switch(config)#         interface range fastEthernet 0/1 - 3
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# exit
Switch(config)#         do wr

then per port — access port guide, exit guide

cisco
Switch(config)#         interface fastEthernet 0/1
Switch(config-if)#      switchport access vlan 10
Switch(config-if)#      no shutdown
Switch(config-if)#      exit
Switch(config)#         do wr

same 4 lines for every row of this table, just swap the port and vlan:

switchportvlandevice
switch0Fa0/1200server0
switch0Fa0/2200pc0
switch0Fa0/320wireless router0
switch1Fa0/110pc4
switch1Fa0/230pc5
switch1Fa0/320wireless router1
switch2Fa0/1100pc2
switch2Fa0/2100pc3
switch4Fa0/110pc7
switch4Fa0/220pc8
switch4Fa0/330pc9
switch2 is the router's switch

its only uplink is the gig facing the 1941 — trunk it like the others. but remember its pcs (pc2/pc3, vlan 100) can only ever ping each other while the router doesn't route

dhcp pool (back on the main switch)

this is what makes vlan 10 special — everything below happens on the 3560's cli (config mode). click back to the main device first

exclude the gateway address first

a pool leases the whole /24 starting at .1 unless told not to — and .1 is the svi you just made
prompt: Switch(config)#

cisco
Switch(config)#         ip dhcp excluded-address 192.168.10.1
Switch(config)#         do wr

create the vlan10 pool

prompt: Switch(config)#

cisco
ip dhcp pool vlan10

the prompt changes to Switch(dhcp-config)# — a pool needs 3 things:

cisco
Switch(dhcp-config)#    network 192.168.10.0 255.255.255.0
Switch(dhcp-config)#    default-router 192.168.10.1
Switch(dhcp-config)#    dns-server 192.168.10.1
Switch(dhcp-config)#    exit
Switch(config)#         do wr
what the 3 lines mean
  • network — the range being handed out: 192.168.10.0/24 (minus the excluded .1)
  • default-router — the gateway pushed to the pc = the vlan 10 svi
  • dns-server — here it matches the svi too

this is the only pool — vlans 20/30/100/200 are all static. and don't add svis on the sub switches, the 3560 stays the only ip owner

enable ip routing

same "optional but do it" step as the other labs — without it the pcs can never ping across vlans — ip routing guide

cisco
Switch(config)#         ip routing
Switch(config)#         do wr
switched the pool on late and a pc already grabbed a bad lease?

clear the lease table and let the pcs re-request — toggle the pc static→dhcp too if it's stubborn

cisco
Switch#                 clear ip dhcp binding *

the router (1941)

turn the ports on — and that's it

click the router → cli tab — enable guide (same ritual, the prompt says Router instead of Switch)

cisco
Router>                 enable
Router#                 configure terminal
Router(config)#
cisco
Router(config)#         interface range gigabitEthernet 0/0 - 1
Router(config-if-range)# no shutdown
Router(config-if-range)# exit
Router(config)#         do wr
this is ALL the router gets — and that's on purpose

no ip addresses, no routing. the class never covered the router side (encapsulation dot1Q on subinterfaces / static routes), so per the rubric the 1941 just needs its ports up. the side effect:

  • pc2 ↔ pc3 works (same vlan, same switch — plain layer 2)
  • pc2/pc3 → anything outside switch2 fails — their pod is stranded behind the router. expected, don't chase it

wireless routers (WRT300N)

these are configured in their gui, not the cli. each one gets its internet port parked inside vlan 20 so the routers themselves can reach the network

internet port — static ip

click wrt300n0 → gui/setup → internet setup → static:

fieldwrt300n0wrt300n1
ip address192.168.20.101192.168.20.102
subnet mask255.255.255.0255.255.255.0
default gateway192.168.20.1192.168.20.1

lan side + dhcp range

leave the lan on its default subnet — pc1, pc6 and smartphone0 pull 192.168.0.x from the wrt300n itself. just split the two dhcp ranges so they can't be confused with each other: router0 hands out 100–150, router1 hands out 151–200

if the rubric mentions wireless settings

ssid/password live in the wrt300n's wireless tab — set them only if asked, any values do

what the devices behind can and can't do

pc1, pc6 and smartphone0 are not required to ping the rest of the network — the rubric only needs the two wireless routers themselves to be reachable (that's why their internet ports sit in vlan 20). tested in #verify

the devices

pc4 and pc7 — dhcp (vlan 10)

click the pc → desktop tab → ip configuration → select DHCP — pc ip setup guide

no typing — the 3560's pool fills everything in (the pc shows "DHCP request successful"):

pcvlanwhat it gets
pc410192.168.10.x / 255.255.255.0 / gateway 192.168.10.1
pc710192.168.10.x / 255.255.255.0 / gateway 192.168.10.1

pc4 and pc7 sit on different switches but the same vlan 10 — the trunks carry it, so one pool serves both

everyone else — static

same desktop → ip configuration → static. dns if the rubric asks = same as the gateway

devicevlanip addresssubnet maskdefault gateway
pc2100192.168.100.10255.255.255.0192.168.100.1
pc3100192.168.100.11255.255.255.0192.168.100.1
pc530192.168.30.10255.255.255.0192.168.30.1
pc930192.168.30.11255.255.255.0192.168.30.1
pc820192.168.20.10255.255.255.0192.168.20.1
server0200192.168.200.10255.255.255.0192.168.200.1
pc0200192.168.200.11255.255.255.0192.168.200.1
these follow the .10 / .11 pattern

swap in whatever you actually typed in the save — the table is the pattern, the save is the truth

pc1, pc6 and smartphone0 need nothing typed — they take whatever the wrt300n's lan dhcp hands them

verify

make sure you're at Switch# (privileged exec, not config mode) and run the standard trio on all six switches — verify guide

cisco
Switch#                 show vlan brief
Switch#                 show interfaces trunk
Switch#                 show ip interface brief

on the 3560 also watch the leases:

cisco
Switch#                 show ip dhcp binding

then from a pc (desktop → command prompt), first check the dhcp side:

bash
ipconfig

pc4/pc7 should show 192.168.10.x with gateway 192.168.10.1

same-vlan across pods — pc5 pinging pc9:

bash
ping 192.168.30.11

inter-vlan — pc5 pinging pc8 (needs ip routing on the 3560):

bash
ping 192.168.20.10

inter-vlan to the server — pc8 pinging server0:

bash
ping 192.168.200.10

the wireless-router test — pc8 pinging both wrt300n internet ports:

bash
ping 192.168.20.101
ping 192.168.20.102

inside the vlan100 pod — pc2 pinging pc3 (local only):

bash
ping 192.168.100.11
expected failures — don't chase these
  • anything behind a wrt300n (pc1, pc6, smartphone0) pinging out — they live in the wrt's own lan, not required by the rubric
  • pc2/pc3 pinging any other vlan — the 1941 doesn't route (not taught)

first ping may drop 1-2 packets (arp) — run it again, it should pass
